MAPA DE NAVEGACIÓN — Gestión de Línea de Eventos (Timeline)

Contexto
- Botón: abre el submodal de “Gestión de Línea de Seguimiento” para un recluta seleccionado y habilita CRUD de eventos personalizados de timeline.
- Ubicación del botón: templates/components/modals.html
  - Elemento: <button id="btn-gestionar-timeline" onclick="openTimelineModalSafely()"> … </button>
- Módulo JS principal: static/js/reclutas.js (objeto global `Reclutas` / alias `reclutaManager`).

Flujo de Navegación desde el Botón
1) Click en `#btn-gestionar-timeline` → `openTimelineModalSafely()`
   - Archivo: templates/components/modals.html
   - Acción: Resuelve `window.reclutaManager || window.Reclutas`, valida `currentReclutaId`, y llama `openTimelineModal()`.

2) `Reclutas.openTimelineModal()` abre el submodal y carga datos
   - Archivo: static/js/reclutas.js
   - Muestra `#timeline-management-modal` y llama a `fetchAndRenderTimeline()`.

3) `Reclutas.fetchAndRenderTimeline()` realiza GET a la API
   - Endpoint: GET /api/reclutas/<recluta_id>/timeline
   - Propósito: Listar eventos personalizados del recluta.
   - Respuesta esperada (200): { success: true, items: [ { id, date, status, title, description, … } ], count, recluta_id }
   - Render: Pinta lista en `#timeline-list` y estadísticas (`#total-eventos`, `#eventos-completados`, `#eventos-pendientes`).

4) Crear/Editar evento desde el formulario del submodal
   - UI: `#timeline-form` con campos `#event-date`, `#event-status`, `#event-title`, `#event-description`.
   - Acción “Guardar Evento”: `Reclutas.saveTimelineItemApi()`.
   - create (nuevo): POST /api/reclutas/<recluta_id>/timeline
     - Body JSON: { date: 'YYYY-MM-DD', status: 'pending|completed|cancelled', title: '...', description: '...' }
     - Respuesta (201): { success: true, item: { id, … } }
   - update (editar): PUT /api/reclutas/<recluta_id>/timeline/<event_id>
     - Body JSON: campos a actualizar
     - Respuesta (200): { success: true, item: { id, … } }
   - Tras éxito: `fetchAndRenderTimeline()` y ocultar formulario.

5) Eliminar evento desde la lista
   - Acción: `Reclutas.deleteTimelineItemApi(id)`.
   - Endpoint: DELETE /api/reclutas/<recluta_id>/timeline/<event_id>
   - Respuesta (200): { success: true, message: 'Evento eliminado' }
   - Tras éxito: `fetchAndRenderTimeline()`.

6) Cierre del submodal
   - El footer ya no incluye botones. Se cierra con el botón del encabezado (`×`) → `(window.reclutaManager || window.Reclutas).closeTimelineModal()`.

Rutas Backend Relacionadas (Blueprint `api`)
- Archivo: routes/api.py

1) GET /api/reclutas/<int:recluta_id>/timeline
   - Handler: get_timeline_recluta(recluta_id) [login_required]
   - Uso: Cargar eventos para el submodal administrativo.
   - Respuesta: { success, items: [EventoRecluta.serialize()], count, recluta_id }

2) POST /api/reclutas/<int:recluta_id>/timeline
   - Handler: create_timeline_event(recluta_id) [login_required]
   - Uso: Crear evento desde el submodal.
   - Campos requeridos: date (YYYY-MM-DD), status (pending|completed|cancelled), title; description opcional.

3) PUT /api/reclutas/<int:recluta_id>/timeline/<int:event_id>
   - Handler: update_timeline_event(recluta_id, event_id) [login_required]
   - Uso: Editar evento desde el submodal.
   - Validación: utils/validators.py::validate_evento_timeline_data

4) DELETE /api/reclutas/<int:recluta_id>/timeline/<int:event_id>
   - Handler: delete_timeline_event(recluta_id, event_id) [login_required]
   - Uso: Eliminar evento desde el submodal.

Rutas Públicas Relacionadas (Seguimiento por Folio)
- Archivo: routes/api.py

5) GET /api/tracking/<folio>/timeline
   - Handler: get_timeline_folio(folio)
   - Uso: Línea de tiempo pública por folio (portal de seguimiento).
   - Respuesta: { success, folio, nombre_candidato, estado_actual, custom_events: [...], has_custom_events, custom_events_count }
   - Relación con el botón: indirecta (posible uso futuro para Vista Previa).

Componentes de UI (modales y secciones)
- Submodal: templates/components/modals.html → #timeline-management-modal
  - Lista: #timeline-list (botones Editar/Eliminar por evento)
  - Formulario: #timeline-form (Guardar → saveTimelineItemApi)
  - Métricas: #total-eventos, #eventos-completados, #eventos-pendientes
  - Acciones: Agregar Evento, Gestión de Documentos

Frontend — Funciones Clave
- templates/components/modals.html
  - `openTimelineModalSafely()`: puente para resolver `reclutaManager`/`Reclutas` y abrir el submodal.

- static/js/reclutas.js (objeto global `Reclutas`)
  - `openTimelineModal()`: abre modal y dispara carga de datos.
  - `fetchAndRenderTimeline()`: GET /api/reclutas/<id>/timeline y renderiza lista/estadísticas.
  - `addTimelineItem()`, `editTimelineItem(id)`, `cancelTimelineForm()`: manejo de UI del formulario.
  - `saveTimelineItemApi()`: POST o PUT según `currentEditingTimelineId`.
  - `deleteTimelineItemApi(id)`: DELETE.
  - `closeTimelineModal()`: cerrar modal (desde el encabezado).
  - `previewTimeline()`: placeholder sin botón asociado actualmente.

Gestión de Documentos (nuevo)
- Botón: “Gestión de Documentos” (junto a “Agregar Evento”) abre submodal `#documents-management-modal`.
- UI del submodal:
  - Input `#recluta-documento` (accept: PDF) y botón “Subir” → `uploadDocumento()`.
  - Lista `#recluta-documentos-list` (acciones Ver/Eliminar) renderizada por `renderDocumentosList(items)`.
- Rutas API utilizadas:
  - GET    /api/reclutas/<recluta_id>/documentos
  - POST   /api/reclutas/<recluta_id>/documentos  (FormData campo `documento`, PDF)
  - DELETE /api/documentos/<id>
- Almacenamiento de archivos: `static/uploads/reclutas/<id>/documentos/` (creación automática de carpetas).

Modelo y Serialización
- models/evento_recluta.py → Modelo `EventoRecluta` (serialize: id, recluta_id, date, status, title, description, created_at, updated_at)
- models/documento.py → Modelo `Documento` (serialize: id, recluta_id, nombre, url, tipo, tamano, fecha_subida)

Validaciones Backend
- utils/validators.py → `validate_evento_timeline_data(data, is_update=False)`
  - Requeridos al crear: recluta_id, date(YYYY-MM-DD), status, title.
  - Valida: status ∈ {pending, completed, cancelled}; título ≥ 3 caracteres; normaliza date a objeto `date`.
