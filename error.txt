Issue: Modal de crear usuario no guarda y la lista queda en "Cargando usuarios…"

Síntomas
- Al abrir el modal "Crear Nueva Cuenta", el botón guardar no crea la cuenta.
- La sección "Administración de Usuarios" muestra "Cargando usuarios…" de forma permanente.

Causa raíz
- El archivo `static/js/admin.js` se cargaba condicionalmente en `templates/base.html` usando el estado del usuario en tiempo de render del servidor. Cuando el usuario inicia sesión vía AJAX (sin recargar la página), el script de administración nunca se incluye, por lo que:
  - No se inicializan los listeners del formulario (no guarda).
  - No se ejecuta la carga/actualización de la lista de usuarios (queda en loading).

Solución aplicada
- Incluir `static/js/admin.js` siempre en `templates/base.html` (sin condicional). El script es seguro: auto‑verifica la existencia de elementos y maneja respuestas 401/403 sin romper la UI.
- Resultado: tras iniciar sesión como administrador, el modal guarda correctamente (POST /admin/usuarios) y la lista se carga/actualiza (GET /admin/usuarios).

## 2. PROBLEMAS IDENTIFICADOS

### 2.1 PROBLEMA PRINCIPAL: Desconexión entre gestión y visualización

**Descripción:**
Los eventos creados en el modal de gestión de eventos NO aparecen en el seguimiento público porque operan en contextos diferentes:

- **Modal de gestión:** Utiliza `reclutaManager` y el contexto administrativo con autenticación
- **Seguimiento público:** Utiliza APIs públicas sin autenticación que filtran solo eventos "asignados por asesor"

### 2.2 PROBLEMAS ESPECÍFICOS ENCONTRADOS:

#### A) Flujo de datos inconsistente (seguimiento.html línea 994-1003):
```javascript
if (tlResp.ok && tl.success && tl.custom_events && tl.custom_events.length > 0) {
    console.log('Mostrando eventos asignados por el asesor:', tl.custom_events);
    renderCustomTimeline(tl.custom_events);
    timelineRendered = true;
} else {
    console.log('No hay eventos asignados por el asesor');
    renderNoEventsMessage();
    timelineRendered = true;
}
```

**PROBLEMA:** La lógica siempre muestra "sin eventos" porque la API `/api/tracking/<folio>/timeline` devuelve una estructura diferente a la que espera el frontend.

#### B) API inconsistente (routes/api.py línea 1505-1507):
```python
personalizados = EventoRecluta.get_for_recluta(recluta.id)
custom_events = [e.serialize() for e in personalizados]
```

**PROBLEMA:** La API devuelve `custom_events` pero el frontend espera verificar `tl.custom_events` y su longitud, causando fallo en la condición.

#### C) Renderizador confuso (seguimiento.html línea 825-884):
```javascript
function renderCustomTimeline(items) {
    console.log('[RENDER] Iniciando renderCustomTimeline con items:', items);
    // ... lógica de renderizado
}
```

**PROBLEMA:** La función recibe items pero nunca se ejecuta porque la condición en línea 995 siempre falla.

### 2.3 PROBLEMAS TÉCNICOS ADICIONALES:

#### D) Referencias cruzadas en modals.html (línea 573-577):
```javascript

    targetObject = window.Reclutas;
```

**PROBLEMA:** Inconsistencia en nombres de objetos globales entre `Reclutas` y `reclutaManager`.

```python
    eventos = EventoRecluta.get_for_recluta(recluta_id)
```


Esta línea ignora completamente los eventos personalizados y siempre muestra la timeline predeterminada basada en el estado del recluta.

### EVIDENCIA VERIFICADA:

#### 1. **Base de datos confirma eventos guardados:**

### FLUJO PROBLEMÁTICO ACTUAL:
1. Usuario ingresa folio → ✅ API obtiene info básica
2. Frontend carga timeline → ❌ **IGNORA** eventos personalizados
3. Renderiza timeline genérica → ❌ Muestra "Recibida", "En revisión", etc.
4. Eventos personalizados nunca se procesan → ❌ **SE PIERDEN**

### ARCHIVOS PROBLEMÁTICOS ESPECÍFICOS:
- **`static/js/client.js:502`** - Línea que causa el problema
- **`templates/seguimiento.html`** - Tiene lógica correcta pero NO se usa
- **Desconexión**: Hay DOS sistemas de renderizado, se usa el incorrecto

### COMPARACIÓN - LO QUE DEBERÍA PASAR vs LO QUE PASA:

#### ✅ **CÓDIGO CORRECTO** (en seguimiento.html):
```javascript
const events = tl.custom_events || tl.items || [];
if (events.length > 0) {
    renderCustomTimeline(events);  // USA eventos personalizados
}
```

#### ❌ **CÓDIGO PROBLEMÁTICO** (en client.js):
```javascript
${this.renderTimelineItems(info.estado)}  // IGNORA eventos personalizados
```

### SOLUCIÓN REQUERIDA:
Modificar `client.js` para que:
1. Llame a la API `/api/tracking/{folio}/timeline`
2. Verifique si hay `custom_events`
3. Si hay eventos → use `renderCustomTimeline(events)`
4. Si no hay eventos → use timeline genérica como fallback
