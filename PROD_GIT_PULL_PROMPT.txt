INSTRUCTIONS (Linux / Nginx + Gunicorn):

0) Confirm before starting:
   - Repo path: /var/www/template_app (or actual)
   - Target branch (ex: 1.5.6.6)
   - Gunicorn service name (ex: gunicorn, template_app)
   - Nginx service name (nginx)

1) Go to repo and check status:
   - cd /var/www/template_app
   - git rev-parse --show-toplevel
   - git status -sb
   - git branch --show-current
   - git remote -v

2) MANDATORY BACKUP (events, profiles, docs, DB):
   - mkdir -p /var/backups/template_app
   - TS=$(date +%Y%m%d_%H%M%S)
   - BACKUP_DIR=/var/backups/template_app/$TS
   - mkdir -p "$BACKUP_DIR"

   A) Full DB backup:
      - /scripts/backup_db.sh "$BACKUP_DIR"
      - (If script does not exist)
        set -a
        [ -f .env ] && . ./.env
        set +a
        mysqldump -u "${MYSQL_USER}" -p"${MYSQL_PASSWORD}" -h "${MYSQL_HOST}" -P "${MYSQL_PORT:-3306}" "${MYSQL_DB}" > "$BACKUP_DIR/db.sql"

   B) Full CSV backup (events, reclutas, users, etc):
      - python scripts/export_data.py
      - LATEST=$(ls -dt backup_* | head -1)
      - mv "$LATEST" "$BACKUP_DIR/"

   C) Backup uploaded files (profiles + docs):
      - tar -czf "$BACKUP_DIR/uploads.tar.gz" uploads/

   D) Save migration state:
      - flask db current > "$BACKUP_DIR/db_current.txt"
      - flask db history > "$BACKUP_DIR/db_history.txt"

3) Local changes:
   - If there are local changes: choose STASH or ABORT
   - Recommended stash:
     git stash push -u -m "prod-pull-$TS"

4) Update code:
   - git fetch --all --prune
   - git pull --ff-only origin <branch>
   - If ff-only fails: stop and review (no merge in prod)

5) Dependencies and migrations:
   - source .venv/bin/activate  (or venv/bin/activate)
   - python -m pip install --upgrade pip
   - python -m pip install -r requirements.txt --no-cache-dir
   - flask db upgrade 2>&1 | tee "$BACKUP_DIR/migration.log"

6) Verify DB schema (avoid 502 errors):
   - python scripts/diagnostico_db.py | tee "$BACKUP_DIR/db_diagnostico.log"
   - If any required table is missing (ex: user_session), fix before restart:
     - Run migrations again: flask db upgrade
     - If no migrations exist for new tables, last resort:
       python -c "from app_factory import create_app; from models import db; app=create_app('production'); app.app_context().push(); db.create_all()"

7) Critical services (before app restart):
   A) Redis
      - systemctl status redis (or redis-server)
      - systemctl start redis (if down)
      - redis-cli ping -> PONG

   B) MySQL/MariaDB
      - systemctl status mysql (or mariadb)
      - systemctl start mysql (if down)
      - mysqladmin ping -u root -p

8) Clear Redis cache (optional but recommended):
   - redis-cli KEYS "metrics_cache_*" | xargs redis-cli DEL

9) Restart services in order:
   - sudo systemctl restart gunicorn
   - sudo systemctl restart nginx
   - sudo systemctl status gunicorn --no-pager
   - sudo systemctl status nginx --no-pager

10) Quick validation:
   - curl -I https://tu-dominio
   - Landing page loads with:
     * Background image sharp (not blurry)
     * Content centered on screen
     * 3 steps visible (En revisión, Entrevista, Resultado)
     * "Acceso de Usuarios Internos" button below steps
     * Version badge (v1.5.6.7) centered at bottom
   - Login works
   - Timeline shows collapsible comments
   - Advanced metrics -> Actividad validation:
     * Tab "Actividad de Usuarios" loads without errors
     * Green badge "Datos en tiempo real" appears (NOT yellow "Modo demostración")
     * KPIs show real numbers (usuarios activos, sesiones, etc.)
     * Users online section shows actual connected users
     * Activity table shows real user data
     * If yellow badge appears, check server logs for endpoint errors

11) If stash was used:
   - git stash list
   - decide apply or keep

TROUBLESHOOTING:
=============================================================================
A) CSS/Styles not updating (old design showing):
   - Clear browser cache (Ctrl+Shift+R or Ctrl+F5)
   - Clear Nginx cache:
     sudo rm -rf /var/cache/nginx/*
     sudo systemctl restart nginx
   - Verify CSS file updated:
     ls -la static/css/styles.css
     head -50 static/css/styles.css | grep "LANDING PAGE"

B) Background image blurry:
   - Check image exists: ls -la static/img/fondo.png
   - Verify image resolution (should be 1920x1080 or higher)
   - If still blurry, may need higher resolution source image

C) Layout not centered:
   - Hard refresh browser (Ctrl+Shift+R)
   - Check CSS loaded: DevTools -> Network -> styles.css (200 OK)
   - Verify no local CSS overrides

D) User Activity showing "Modo demostración" (yellow badge):
   - Check endpoint works: curl -I https://tu-dominio/admin/metricas/actividad-usuarios
   - Review server logs for errors:
     sudo journalctl -u gunicorn -n 100 --no-pager | grep -i "actividad\|error"
   - Verify UserSession table exists:
     python -c "from models import UserSession; print('OK')"
   - Check database connection is working
   - If endpoint returns 500, check traceback in logs
   - Click "Cargar datos reales" button to retry

NOTES:
- REDIS_URL must point to your Redis instance (local or cloud).
- In production, Redis must always be running.
- Static files (CSS, JS, images) may be cached by Nginx or browser.
- After CSS changes, always clear caches and hard refresh.
- If anything fails, use backups in /var/backups/template_app/$TS.
